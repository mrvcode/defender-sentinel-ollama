
Hay dos tipos de regla en el portal de Defender, y solo uno sirve:

> [!info] Comparación: Regla de Automatización Estándar vs. Mejorada
> | Característica | Regla estándar | Regla mejorada (Enhanced) |
> | :--- | :---: | :---: |
> | **Ámbito** | Un workspace de Sentinel | Todo el tenant |
> | **Puede lanzar Logic Apps** | Sí | No |
> | **Puede lanzar playbooks generados por IA (Python)** | No | Sí |

### Crear la regla

1. Portal de Defender → **Microsoft Sentinel → Configuration → Automation** (_Configuración → Automatización_) → pestaña **Reglas estándar** → **Crear**.
2. Rellena los campos:

| Campo                      | Valor                                                                                     |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| Nombre                     | el que quieras                                                                            |
| Desencadenador (_Trigger_) | **Cuando se crea el incidente** (_When incident is created_)                              |
| Área de trabajo            | tu workspace de Sentinel (sino lo desactivas antes no podrás desplegarlo)                 |
| Condiciones                | ver nota abajo                                                                            |
| Acción                     | **Ejecutar cuaderno de estrategias de aplicación lógica** (_Run playbook_) → tu Logic App |
| Orden                      | `1` (si hay otras reglas, se ejecutan en este orden; no bloquea nada)                     |
| Estado                     | Activo                                                                                    |

3. Guarda.

### Sobre las condiciones

- **Sin condiciones**, la regla se lanza con **cada incidente nuevo**. Elegí este caso para pruebas.
- Una condición de título debe usar **Contiene**, no **Es igual a**: el título real de un incidente de EICAR es del tipo `'EICAR_Test_File' malware was prevented`, no `EICAR`. Este ejemplo es el que se puede usar para acotar la prueba para que lance la app de Ollama con una prueba tipo.  
- La condición **Nombre de la regla de análisis** no sirve para incidentes creados por Defender: no tienen regla analítica asociada.

### Regla de oro de los triggers

|Regla de automatización|Logic App con trigger|
|---|---|
|Cuando se crea el **incidente**|_Microsoft Sentinel incident_ ✅|
|Cuando se crea la **alerta**|_Microsoft Sentinel alert_|

Si no coinciden, la Logic App no aparece en la lista de playbooks.
