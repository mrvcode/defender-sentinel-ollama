**Privacidad**

- Que el modelo sea local no significa que los datos no salgan: pasan por el túnel. No envíes datos sensibles reales.
- No subas a GitHub URLs de ngrok, identificadores de suscripción, tenant, workspace, nombres de equipo ni usuarios.

**Fiabilidad de las respuestas** (casos reales de este laboratorio)

- Dijo que _"no se proporciona hash"_ cuando los dos hashes iban en los datos.
- Inventó el significado de las siglas de EICAR y escribió recomendaciones sin apoyo en los datos.
- Trató IPs del propio equipo como sospechosas cuando no había ningún motivo.
- Ignoró el formato pedido en varias ejecuciones, incluso con temperatura baja.

**Recomendaciones**

- Trata el comentario como una **ayuda al analista**, no como un veredicto. Nunca automatices acciones de respuesta a partir de lo que dice la IA.
- Prueba cada cambio de prompt varias veces: el modelo no es determinista y un resultado aislado no dice nada.
- Cambia **una cosa cada vez** en el prompt; los retoques acumulados hicieron que el resultado empeorara.
- Envía solo los campos que necesitas. Un JSON de entidades muy grande alarga la respuesta y puede hacer que el modelo pierda las instrucciones.
- Las instrucciones sobre IPs tienen límites: un modelo no distingue por sí solo las IPs propias de las ajenas. Una solución más robusta sería filtrar las entidades por tipo antes de enviarlas (no probado en este laboratorio).
